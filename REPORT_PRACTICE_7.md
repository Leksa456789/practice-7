# Отчет по практическому занятию №7. Анализ потоков данных, дизассемблирование и линтинг.

## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек

Нумерация строк без пустых:

```python
1  def process_transaction(user_id, amount, db_connection):
2      log_entry = "Start processing"
3      if amount > 0:
4          status = "approved"
5          balance = get_balance(user_id)
6          new_balance = balance - amount
7          update_balance(user_id, new_balance)
8      log_entry = "Transaction finished with status: " + status
9      file = open("audit_log.txt", "w")
10     file.write(log_entry)
11     return status
```

| Переменная | Def | Use |
|---|---|---|
| log_entry | строки 2 и 8 | строка 10 (значение из строки 2 не читается) |
| status | строка 4 (только при amount > 0) | строки 8 и 11 |
| balance | строка 5 | строка 6 |
| new_balance | строка 6 | строка 7 |
| file | строка 9 | строка 10, закрытия нет |

### 1.2. Описание выявленных дефектов

- **Дефект 1 (Неинициализированная переменная):** `status` определяется
  только в строке 4 внутри `if amount > 0`. При `amount <= 0` ветка
  пропускается, и в строке 8 (затем в строке 11) переменная читается без
  значения. Возникает `UnboundLocalError`.
- **Дефект 2 (Мертвое присваивание):** значение `"Start processing"` из
  строки 2 перезаписывается в строке 8 и ни разу не читается (Dead Store).
- **Дефект 3 (Утечка ресурса):** файл открывается в строке 9, но не
  закрывается. Дескриптор остается занятым, данные могут не сброситься на
  диск, а при исключении в `write` закрытие тоже не произойдет.

## 2. Дизассемблирование

### 2.1. Восстановленный код на Python

```python
def sum_to_10():
    total = 0
    i = 1
    while i <= 10:
        total += i
        i += 1
    return total
```

### 2.2. Краткое пояснение логики

По адресу -4(%rbp) хранится аккумулятор sum (обнуляется), по адресу
-8(%rbp) счетчик i (начальное значение 1). Инструкция `jmp .L2` сразу
переходит к проверке `cmpl $10, -8(%rbp)`. Пока i <= 10 (`jle .L3`),
выполняется тело цикла: sum += i, i += 1. После выхода из цикла sum
помещается в `%eax` как результат. Функция вычисляет сумму чисел от 1 до 10,
результат 55.

## 3. Деобфускация

### 3.1. Расшифрованная строка

```
import os; os.system('rm -rf /')
```

### 3.2. Анализ угрозы

Через `exec` выполняется системная команда `rm -rf /`, которая рекурсивно и
без подтверждения удаляет все файлы, начиная с корня файловой системы.
Последствия: потеря данных и самой ОС, отказ системы. При запуске от root
ущерб максимален. Обфускация (Base64) скрывает вредоносную логику.

### 3.3. Методы защиты

- Не использовать `exec` и `eval` с недоверенными данными.
- Валидировать и фильтровать входные данные.
- Использовать статический анализ (flake8, bandit) для поиска `exec`,
  `os.system` и декодирования с последующим выполнением.
- Проводить code review подозрительных закодированных строк.
- Запускать код с минимальными правами в изолированной среде
  (контейнер, песочница), не работать под root.

- `max-line-length = 80`: максимальная длина строки 80 символов.

  двоеточием) и W503 (перенос строки перед бинарным оператором).
